# ALL IN MACAU — 2026 DT Outing 테이블 대항 게임

80~120명이 **휴대폰으로 QR을 찍고 들어와** 테이블(조)별로 겨루는 게임입니다. 로그인 없이 링크만으로 접속합니다.

| 라운드 | 게임 | 칩 |
|---|---|---|
| 1 | **얼굴 카드** — 테이블 번호 순서대로 카드 2장을 뒤집어 같은 사람 찾기 → 모든 테이블이 그 사람 이름 맞히기 | 짝 +100, 이름 정답 +50 |
| 2 | **소수의 선택** — 가장 적은 테이블이 고른 보기가 승리 (문제당 30초, 시간이 끝나면 자동 발표) | 소수 +100 |
| 3 | **룰렛** — 모은 칩을 빨강/검정에 베팅 (베팅 60초, 안 걸면 그 판은 건너뜀) | 맞히면 2배 |

마지막에 칩이 가장 많은 테이블이 우승합니다. 모두 0칩으로 시작합니다.
얼굴 카드 인물을 등록하지 않으면 소수의 선택(1라운드) → 룰렛(2라운드)으로 진행합니다.

| 화면 | 주소 | 누가 |
|---|---|---|
| 참가자 | https://macau-roulette.onrender.com | 참가자 폰 (빔 화면의 QR을 찍으면 열림) |
| 빔 | https://macau-roulette.onrender.com/beam | 스크린에 띄우는 노트북 (조작 없음) |
| 운영자 | https://macau-roulette.onrender.com/host | 진행자 (운영자 비밀번호 = Render의 `HOST_PIN`) |

## 1. 행사 운영 매뉴얼

### 예상 시간 (테이블 10개 기준, 약 1시간)
| 순서 | 시간 |
|---|---|
| 입장 + 오프닝 | 5분 |
| 1라운드 얼굴 카드 (8~12명) | 10~15분 |
| 2라운드 소수의 선택 (질문 1개 ≈ 1분) + 중간 순위 | 질문 수만큼 (기본 20개 = 20분) |
| 3라운드 룰렛 (기본 3회, 회당 베팅 60초 + 회전 10초) | 6~8분 |
| 최종 발표 | 3분 |

시간 조절은 **운영자 화면 → 게임 설정**에서 소수의 선택 질문 수·선택 시간, 룰렛 횟수·베팅 시간으로 합니다. 얼굴 카드는 진행 중 "이번 차례 끝나면 종료"로 일찍 끝낼 수 있습니다.

### 행사 전 준비 (체크리스트)
1. [ ] **마지막 배포를 먼저** 끝냅니다 (아래 4장). 배포하면 서버에 올린 사진·진행 상태가 지워지기 때문입니다.
2. [ ] 운영자 화면 로그인 → **게임 설정**
   - **얼굴 카드 인물**: "+ 사진 여러 장 추가"로 사진을 한꺼번에 올립니다. **파일 이름이 이름**이 됩니다 (`홍길동.jpg` → 홍길동). 영문 이름·별명은 "다른 표기"에 쉼표로 적으면 정답으로 인정합니다. **인물 저장** 클릭.
   - **"파일로 내려받기(백업)"** 로 백업 파일을 받아 둡니다. 사진이 사라지면 "백업 파일 불러오기"로 한 번에 복구합니다.
   - 테이블 수, 소수의 선택 질문, 룰렛 횟수 확인 → **설정 저장**.
3. [ ] **새 게임 만들기** (설정 탭 오른쪽 위). 설정·인물은 새 게임에 그대로 이어집니다.
4. [ ] 행사 10분 전 빔 화면을 열어 둡니다 (무료 플랜은 잠들어 있으면 첫 접속에 30~60초 걸림).
5. [ ] Render의 **Auto-Deploy가 꺼져 있는지** 확인 (행사 중 재배포 방지).

### 당일 진행 (화면 흐름)
운영자 화면 **게임 진행** 탭의 노란 버튼을 위에서부터 순서대로 누르면 됩니다. 버튼 위에 지금 할 일이 적혀 있습니다.

| 순서 | 빔 화면 | 운영자 버튼 |
|---|---|---|
| 대기실 | QR · 입장 현황 · 오늘의 게임 3라운드 소개 | 1라운드 얼굴 카드 안내 |
| 1라운드 안내 → 진행 | 규칙 → 카드판 (차례 · 남은 시간) → 짝을 찾으면 이름 맞히기 → 정답 공개 | 얼굴 카드 시작 (이후 자동 진행) |
| 1라운드 결과 | 찾은 사람 · 테이블별 칩 | 2라운드 소수의 선택 안내 |
| 2라운드 안내 → 연습 → 본게임 | 문제 · 남은 시간 · 제출 현황 → 결과 | 연습 질문 → 본게임 → 다음 질문 (시간이 끝나면 자동 발표) |
| 중간 순위 | 라운드별 획득 칩과 순위 | 3라운드 룰렛 안내 |
| 3라운드 룰렛 | 베팅 남은 시간 · 테이블별 베팅 현황 → 회전 → 결과 | 룰렛 베팅 시작 → 룰렛 돌리기 → 다음 룰렛 |
| 최종 결과 | 1~3위 시상대 + 전체 순위 | (끝) |

참가자는 게임 중에도 늦게 입장할 수 있습니다 (0칩으로 시작, 얼굴 카드 중이면 마지막 차례).

**타이머 조작** (얼굴 카드 · 소수의 선택 · 룰렛 베팅 중 운영자 화면에 표시): **⏸ 일시정지 / ▶ 재개**, **+15초**. 일시정지하면 참가자·빔 화면에 "진행자가 잠시 멈췄어요"가 뜨고 시간이 멈춥니다. 멘트가 길어질 때 쓰세요.

**막혔을 때**
| 상황 | 방법 |
|---|---|
| 얼굴 카드: 차례인 테이블이 안 고름 | 30초 지나면 자동으로 무작위 선택. 급하면 "시간 마감" |
| 얼굴 카드: 시간이 부족 | "이번 차례 끝나면 얼굴 카드 종료" |
| 룰렛: 한 테이블이 베팅을 안 함 | 60초가 지나면 자동으로 건너뜀. 급하면 테이블 현황에서 "베팅 건너뛰기" |
| 룰렛: 베팅 시간이 끝났는데 더 받아야 함 | "베팅 15초 다시 열기" |
| 채점 오류·항의 | **점수 확인 → 칩 직접 조정** (+50 / −50, 사유 기록) |
| 오지 않은 테이블 | 대기실에서 "불참 처리" (게임 중엔 "제외") |
| 참가자 폰이 끊김 | 다시 링크를 열면 같은 테이블로 자동 복귀 |
| 운영자 화면을 닫음 | 다시 열면 로그인 상태 유지. 게임은 서버에서 계속 진행됨 |

### 개인정보
- 얼굴 사진은 **카드가 뒤집힐 때만** 참가자에게 전송되고, 인물 이름 목록은 **운영자 화면에만** 보입니다. 빔·폰의 카드판에는 이름이 나오지 않습니다.
- 사진은 서버에만 저장되고 **GitHub 저장소에는 올리지 않습니다** (저장소가 공개 상태). 백업 파일도 개인 PC에 보관하세요.

## 3. Git / GitHub 사용법 (처음이라면)

**용어**
- **저장소(repository)**: 이 프로젝트 파일 전체와 변경 기록이 저장된 곳 (github.com/sun-woosh/outing_game)
- **커밋(commit)**: "이렇게 바꿨다"는 저장 기록 한 건
- **브랜치(branch)**: 같은 프로젝트의 별도 작업 공간. 다른 브랜치에서 고쳐도 main은 그대로임
- **PR(Pull Request)**: "이 브랜치의 변경을 main에 합쳐 주세요"라는 요청서. GitHub에서 **Merge** 버튼을 누르면 합쳐짐

**브랜치 안내**
| 브랜치 | 용도 | 해야 할 일 |
|---|---|---|
| `main` | **실제 서비스용**. Render가 이 브랜치를 배포 | 여기만 기준으로 보면 됨 |
| `claude/vigilant-noether-n2u7tw` | Claude가 작업하는 브랜치. 수정은 여기 올라온 뒤 PR로 main에 합쳐짐 | 직접 건드릴 필요 없음 |
| `import/sites-v1`, `import/townhall-face-card` | 원본 보관용. 내용은 이제 `reference/` 폴더에 들어 있음 | 지워도 됨 (GitHub → Branches → 휴지통 아이콘) |

**수정이 반영되는 흐름**
```
Claude에게 요청 → Claude가 claude/... 브랜치에 올리고 PR 생성
→ 사용자가 GitHub에서 PR 확인 후 [Merge pull request] → [Confirm merge]
→ Render에서 [Manual Deploy] → [Deploy latest commit] → 2~3분 후 반영
```

**주의**
- **행사 중에는 Merge·Deploy 하지 않기** — 서버가 재시작되어 진행 상태와 사진이 지워집니다.
- GitHub 웹에서 파일을 직접 고쳐도 되지만, `client/`나 `server/`를 고치면 `dist/`(빌드 결과)도 다시 만들어야 반영됩니다. 직접 고치기보다 Claude에게 요청하는 것을 권장합니다.

## 4. 배포 (Render)

- 서비스: Render의 `macau-roulette` (브랜치 `main`). 빌드 명령 `npm ci --omit=dev`, 시작 명령 `node server.js` — `dist/`가 저장소에 포함되어 있어 Render에서 따로 빌드하지 않습니다.
- 운영자 비밀번호: Render → Environment → `HOST_PIN`
- **인스턴스는 1대만** (Autoscaling 끄기). 게임 상태를 서버 메모리에 둡니다.
- 무료 플랜: 15분간 접속이 없으면 잠들고(깨는 데 30~60초), 재시작·재배포하면 진행 상태와 사진이 지워집니다. 유료(0.5c-512mb, 월 $7)도 재배포하면 지워지는 것은 같습니다.

## 5. 개발자용

```bash
npm install
```

```bash
npm run build
```

```bash
HOST_PIN=2026 npm start
```

`http://localhost:3000` (참가자) · `/beam` · `/host`. 코드를 고친 뒤에는 반드시 `npm run build`를 하고 **`dist/`까지 함께 커밋**해야 Render에 반영됩니다.

```bash
npm test
```

부하 테스트 (⚠ 대상 서버에 새 게임이 만들어지니 행사 전에만):

```bash
HOST_PASSWORD=운영자비번 node scripts/loadtest.cjs https://macau-roulette.onrender.com 120 14
```

| 환경 변수 | 기본값 | 설명 |
|---|---|---|
| `HOST_PIN` (또는 `GAME_HOST_PASSWORD`) | 없음 | 운영자 비밀번호. 없으면 운영자 로그인 불가 |
| `PORT` | 3000 | |
| `DATA_DIR` | `./data` | 진행 상태(`state.json`)와 사진(`photos/`) 저장 위치 |

### 구조 요약
- 서버 한 대가 게임 상태를 메모리에 두고 요청을 **순서대로** 처리합니다 (1초마다 파일 백업).
- 화면은 WebSocket(Socket.IO)으로 연결되어, 상태가 **바뀔 때만** 서버가 밀어 줍니다. 같은 테이블·역할끼리 묶어 한 번만 계산합니다.
- 검증: 가상 폰 120대 / 14테이블로 얼굴 카드 → 소수의 선택 → 룰렛 전체 진행, 실패 요청 0건, 응답 최대 44ms, 서버 메모리 약 100MB.

### 예전 버전(Codex · ChatGPT Sites)이 먹통이 된 이유
| 원인 | 지금 |
|---|---|
| 모든 화면이 1.5초마다 서버에 상태를 요청 (90명이면 초당 60건+) | 바뀔 때만 서버가 전송 |
| 게임 전체를 DB 한 행에 저장, 동작마다 충돌 시 최대 64번 재시도 | 메모리에서 순서대로 처리 (충돌 없음) |
| ChatGPT 로그인 필수 | 로그인 없음 |
