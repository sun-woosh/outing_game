# 🎰 마카오 룰렛 (DT Outing 2026)

80~100명이 휴대폰으로 동시에 참여하는 **조 대항 룰렛 게임**입니다.
로그인 없이 링크(QR)만으로 누구나 접속하고, 서버 한 대로 150명 동시 접속까지 검증했습니다.

| 화면 | 주소 | 용도 |
|---|---|---|
| 참가자 | `/` | 휴대폰. 이름 입력 + 조 선택 → 베팅 |
| 빔 | `/beam` | 스크린 송출. QR, 룰렛 휠, 조 순위, 최종 시상 |
| 운영자 | `/host` | 진행자 노트북/폰. PIN 로그인 후 진행 버튼 |

## 게임 규칙 (약 10~12분)

- 모두 **칩 1,000개**로 시작, 총 **5라운드** (라운드당 베팅 40초 + 회전 9초 + 결과 발표)
- 베팅: 빨강/검정 · 홀/짝 · 1-18/19-36 → **2배**, 12개 묶음 → **3배**, 숫자 하나 → **36배**, 0이 나오면 바깥 베팅은 전부 패배
- **우승: 조원 1인 평균 칩이 가장 많은 조** (조 인원이 8명이든 10명이든 공정)
- 칩을 다 잃어도 다음 라운드에 **구조 칩 200개** 지급 → 끝까지 모두 참여
- 라운드 이벤트 (운영자 화면에서 변경 가능)
  1. 일반
  2. 🤝 **팀워크**: 우리 조 베팅 참여자의 70% 이상이 맞히면 조원 **전원 +200**
  3. 🍀 **럭키 넘버**: 라운드 시작 때 공개되는 숫자에 걸면 **50배**
  4. 일반
  5. 💰 **잭팟**: 모든 당첨 수익 **2배** (역전 기회)
- 휴대폰에는 **우리 조가 어디에 몇 명 걸었는지** 실시간 표시 → 조끼리 상의하게 만드는 장치

## 진행 대본 (사회자용)

1. **입장 (2~3분)** 빔에 `/beam` 띄우기 → "화면 QR 찍고 이름과 조 선택해 주세요." 운영자 화면에서 인원 확인
2. **라운드 1** "▶ 라운드 1 시작" → "40초 안에 칩 고르고 칸을 누르세요! 우리 조 화면에 누가 어디 걸었는지 보입니다."
3. 타이머가 끝나면 자동 마감 → **"🎡 룰렛 돌리기"** → 결과 발표, 빔에 이번 라운드 TOP 5
4. 라운드 2~5 반복. 이벤트 라운드는 빔과 폰에 배너로 자동 안내 (팀워크 라운드 전에 "조끼리 한 곳에 몰아 보세요!" 멘트 추천)
5. 마지막 라운드 후 **"🏆 최종 결과 발표"** → 빔에서 3위 → 2위 → 1위 순으로 공개, 개인 MVP 5명

> 빔 화면 오른쪽 아래 **🔊 소리 켜기**를 한 번 눌러야 효과음이 납니다 (브라우저 정책).

## 배포 (로그인 없는 공개 링크)

ChatGPT Sites는 접속 시 ChatGPT 로그인이 필요하고(회사 보안 이슈), 동시 접속에 맞춘 구조가 아니었습니다.
이 버전은 일반 Node.js 서버라 어디든 올릴 수 있습니다. **반드시 인스턴스 1대로** 운영하세요 (상태를 메모리에 둠).

### A. Render (가장 쉬움, 무료 가능)

1. https://render.com 가입 → **New → Blueprint** → 이 GitHub 저장소 선택 (브랜치 지정 가능)
2. `HOST_PIN` 값 입력 (운영자 PIN) → Deploy
3. 발급된 `https://macau-roulette-xxxx.onrender.com` 이 공개 링크입니다 (`/beam`, `/host`)

- 무료 플랜은 **15분 동안 접속이 없으면 잠들고 깨는 데 30~60초** 걸립니다 → 행사 10분 전에 빔 화면을 미리 열어 두세요. 당일만 **Starter($7/월)** 로 올리면 잠들지 않습니다.
- 무료 플랜은 재배포/재시작 시 진행 상태가 초기화됩니다. 행사 중에는 재배포하지 마세요.

### B. Docker (Fly.io, Railway, 사내 서버 등)

```bash
docker build -t macau-roulette .
```

```bash
docker run -p 3000:3000 -e HOST_PIN=1234 -v $(pwd)/data:/app/data macau-roulette
```

### 환경 변수

| 이름 | 기본값 | 설명 |
|---|---|---|
| `HOST_PIN` | `2026` | 운영자 PIN. **꼭 바꾸세요** |
| `PUBLIC_URL` | (자동) | QR에 넣을 주소. 프록시 뒤에서 주소가 틀리게 나오면 지정 |
| `PORT` | `3000` | |
| `DATA_DIR` | `./data` | 상태 자동 저장 위치 (서버가 재시작돼도 이어서 진행) |

## 예전 버전이 먹통이 된 이유와 이번 구조

| 문제 | 이번 버전 |
|---|---|
| ChatGPT 로그인 필수 → 80명이 동시에 로그인/리다이렉트 | 로그인 없음. QR만 찍으면 바로 입장 |
| 폰마다 서버를 주기적으로 조회(폴링) → 요청 폭주 | WebSocket 1개로 서버가 변경분만 전송 (막힌 망은 자동 폴링 전환) |
| 베팅마다 전체 상태 전송 | 0.4초 단위로 묶어서 전송, 개인 정보는 해당 폰에만 |
| 새로고침/화면 꺼짐 시 이탈 | 토큰 저장 → 자동 재접속·복구, 화면 꺼짐 방지(Wake Lock) |
| 연타 시 중복 베팅 | 요청 ID로 중복 무시, 서버가 칩 검증 |
| 재접속이 한꺼번에 몰림 | 재접속 대기시간 무작위 분산 |

검증 결과 (150명, 3라운드, 베팅 1,500건): 오류 0건, 응답시간 p50 1ms · p99 7ms, 서버 메모리 약 90MB.
